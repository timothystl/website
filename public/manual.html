Editing Static Text on Pages

Most of the text on the site — page titles, descriptions, service times, the "About" paragraphs, ministry page copy — lives directly in public/index.html. This file contains the entire site.

Easiest way: Describe the change to Claude. E.g. "Change the Food Pantry page headline from 'Caring for Neighbors' to 'Feeding Our Neighbors'". Claude will find the exact spot and make the edit.

If you want to find it yourself

Open public/index.html and search (Ctrl+F / Cmd+F) for a unique phrase from the page you're editing — for example a few words from the heading or paragraph you want to change. Each page section starts with a comment like:

<!-- FOOD PANTRY -->
<div id="page-foodpantry" class="page">

What you can safely edit vs. what to avoid

  • Safe to edit: Any visible text between > and < tags — headings, paragraphs, labels.
  • Safe to edit: URLs in href="..." values — links, email addresses.
  • Be careful with: Any line that has style="...", class="...", or JavaScript (onclick="...") — changing these can break layouts or navigation.
  • Don't touch: Lines that start with <script>, function, or contain fetch( — that's the code that makes the page work.

Note on admin-managed sections: Some parts of ministry pages show content from the admin portal (volunteer posts, seasonal blocks, ministry announcements). These are separate from the static HTML text. The static text is the "always-there" foundation; admin-managed content layers on top.

Adding a Header Photo to a Ministry Page

Each ministry landing page has a hero section at the top — the big colored banner with the page title. Right now they all show a solid steel-blue color. When you have a photo for a page, here's how to add it.

Pages that support header photos: Music, Stephen Ministry, Food Pantry, Urban Beekeepers, Christmas Market. The Christmas Market page already has its photo set.

Step 1 — Get the photo ready

Photos work best when they are:

  • Landscape orientation (wider than tall)
  • At least 1400px wide (wider = looks better on large screens)
  • JPG or WebP format (smaller file sizes)
  • Not too "busy" in the center — the text overlays the middle, so a photo with open sky or soft background works well

Step 2 — Upload the photo

Place the photo in /public/images/ministries/ in the website repository. Name it clearly, e.g. music-hero.jpg, stephen-hero.jpg, foodpantry-hero.jpg, bees-hero.jpg.

If you're working with Claude, just say: "Add this photo as the header image for the Music Ministry page" and share the file.

Step 3 — Edit the hero div in public/index.html

Find the ministry page section (search for e.g. id="page-music") and look for the hero div. It will have a comment above it saying exactly what to add:

<!-- Hero: add style="background-image:url('...')" when photo is available -->
<div class="page-hero page-hero--photo">

Change it to:

<div class="page-hero page-hero--photo"
     style="background-image:url('/images/ministries/music-hero.jpg');">

The overlay (dark blue tint that makes text readable) is applied automatically — you don't need to add anything else.

Easier option: Just tell Claude: "Add music-hero.jpg as the header photo on the Music Ministry page." Claude knows exactly where to put it.

How the Christmas Market photo is set (for reference)

The Christmas Market page already has its header photo. Here's what it looks like in the code — the same pattern applies to any ministry page:

<div class="page-hero page-hero--photo"
     style="background-image:url('/images/ministries/Christmas-MKT.jpg');">
  ...page title and subtitle here...
</div>

Editing Buttons on Ministry Pages

Every ministry landing page has a light warm-white button bar at the very bottom of the page. Each button can be changed independently — you can edit the text, change the link, or hide a button you don't need.

Where to find them in the code

Each button bar is marked with a comment block that looks like this:

<!-- ══════════════════════════════════════════
     CHRISTMAS MARKET PAGE — CTA BUTTON BAR
     UPDATE ANNUALLY — change these each fall...
     ══════════════════════════════════════════ -->

Just search for the page name (e.g. CHRISTMAS MARKET PAGE — CTA BUTTON BAR) and you'll jump right to it.

Changing button text

The text that appears on the button is between > and </a>. Edit only that text:

<!-- Button 1: Vendor application -->
<a href="mailto:office@timothystl.org" class="btn btn-primary">Apply to be a vendor</a>

Changing where a button links

Edit the href="..." value. Common patterns:

<!-- Link to a website -->
href="https://docs.google.com/forms/your-form-id"

<!-- Send an email -->
href="mailto:office@timothystl.org"

<!-- Pre-fill email subject line -->
href="mailto:office@timothystl.org?subject=Vendor Application"

Hiding a button temporarily

Add style="display:none;" to the <a> tag. Remove it to show it again:

<a href="..." class="btn btn-primary" style="display:none;">Apply to be a vendor</a>

Easier option: Tell Claude what you want. For example: "Change the vendor button on the Christmas Market page to link to this Google Form: [paste URL]" — Claude will make the edit correctly.

Seasonal Worship Blocks

Seasonal worship blocks are optional content sections that appear on the Worship page (/worship). There are five, one for each major season. Each can be written once and then toggled on or off — so you can set up the Advent block in November, turn it on, then turn it off in January without losing your content.

Where to find them

Go to admin.timothystl.org/pages and look for:

  • Lent / Midweek worship — Midweek Lenten services, extra services during Lent
  • Holy Week & Easter — Palm Sunday, Maundy Thursday, Good Friday, Easter services
  • Thanksgiving worship — Thanksgiving Eve or Day service
  • Advent worship — Midweek Advent services, special series
  • Christmas services — Christmas Eve and Christmas Day service times

How to use them

Step 1 — Write the content

Click Edit on the seasonal block. Enter the service times, dates, and any description. You can use the rich text editor to add headings, bold text, or a simple table of service times. Click Save & Publish and check the "Show this block on the website" box.

Step 2 — Turn it on

Make sure the "Show this block on the website" checkbox is checked when you save. The block will appear on the Worship page immediately.

Step 3 — Turn it off when the season ends

Go back to the block, uncheck "Show this block on the website," and save. The content stays saved — ready for next year. The block disappears from the site.

Where does the block appear on the Worship page? It shows up between the "Service Times" section and the "Where Tradition Meets the Unexpected" section — right in the middle of the page where visitors will see it easily.

Community Concerts

The Music Ministry page has a dedicated Community Concert announcement section that appears when a concert is coming up. It is hidden between concerts and shown when one is scheduled.

Where to find it

Go to admin.timothystl.org/pages and click Edit on Community Concert announcement.

What to put in the content

Write the concert details in the rich text editor. Include:

  • The performer's name and a brief description
  • Date and time
  • Location (if different from the sanctuary)
  • Admission info (free? donations appreciated?)
  • Any other details

You can add a heading, bold text, and links (e.g. to the performer's website) using the editor toolbar.

Turning it on and off

Check "Show this block on the website" when you save to make it visible on the Music Ministry page. Uncheck it (and save) when the concert is over — your content stays saved for reference.

Updating for each new concert: Just go back to admin → Pages → Community Concert announcement, replace the content with the new performer's info, make sure the checkbox is checked, and save. No code changes needed.

Admin Portal

The admin portal lives at admin.timothystl.org. Sign in with your admin username and password. Contact the office for credentials.

Live Signing in takes you to the Dashboard. It has two views, switched with the buttons at the top right:

  • Needs you (the one it opens on) — a worklist you clear. Gym requests waiting, pages with edits nobody has published, newsletters awaiting approval, website messages held as spam, news posts about to expire. Each one has a single button that takes you to the screen where you deal with it. When there is nothing, it says so.
  • Overview — the same week as four numbers, for when you want the shape of things rather than a list of jobs.

Below the worklist, Our Four Values reports on the church's own priorities rather than on the website's plumbing: how many ministries carry each value, how much has been posted under it in the last month, and which partner ministry is paired to it. A value with nothing new says so plainly.

Navigation lives in the left sidebar, in three groups — Website, Communication, and People & Ops. Ministries, Partners, News & Events, Sermons and Christian Ed sit indented under Pages, because all five of them produce pages on the website; they are separate screens only because different people look after them. A number beside an item is a count of things still waiting on a person, and it is the same number the Dashboard shows. The sidebar stays tucked away behind the menu icon in the top bar — tap it to open, tap outside it to close.

Every list screen works the same way. A title and one button for adding something; a sentence saying what the screen is for; a search box and filter buttons with a count beside them; then the list. Click any row to open it. A row that needs attention grows a strip underneath it saying what is wrong and offering to fix it — a notice with nothing written in it, a news post with no expiry date, a ministry with no core value. At the bottom of every screen there is one line beginning with ◆ explaining the one rule that screen enforces. Learn one screen and you have learned all of them.

News & Events tab

Live Post news items and events that appear on the /news page. Each item has a title, summary (shown on the card), optional full body text (shown on "Read More"), optional card thumbnail image URL, publish date, and expiry date (items hide automatically after they expire). Check Pinned to keep an item at the top of the list regardless of date.

The expiry date is the field that matters. A post that has one takes itself off the website on that day, which is the only thing keeping the site from filling up with last year's announcements. A post without one is flagged in the list, because it will sit there until somebody remembers to remove it. Set it when you write the post, not later.

News and the Newsletter are two separate screens now. News & Events is this one. The newsletter lives under Communication in the sidebar. The /news page on the website shows both, with the church calendar embedded underneath — so anyone asking "what's happening" has one page to look at. /calendar still works as its own page for anyone who has bookmarked it or printed it on a flyer.

To add a photo inside the body text: drag and drop an image file into the editor, or copy-paste one — it uploads to Cloudflare automatically. The card thumbnail field (above the editor) still requires a pasted URL.

Newsletter

Live Newsletter composition lives on the same News & Events page (there's no separate Newsletter item in the sidebar — both share one page since they're managed together). It connects to Brevo and lets you compose and send the congregation email newsletter directly from the admin portal. Choose a format (Weekly or Quick Announcement), write the content, preview it, and either save as a draft or send. This is a separate system from the news items on the website — the newsletter goes out by email, while News & Events appear on the site.

Click Copy next to any draft or past newsletter to duplicate it as a brand-new draft (subject prefixed "Copy of…"), including its events and Bible class list. The copy opens straight in the editor so you can update the date and content, then publish — the original is left untouched.

Live Click Schedule send next to a draft or past newsletter to have Brevo send it automatically at a future date and time instead of right away — pick the date/time and confirm. A blue "⏰ Scheduled for…" badge shows on the newsletter until it goes out; use Cancel schedule to call it off beforehand. Scheduling to "all subscribers" publishes the newsletter to the website archive right away (not at send time) so the "Read the full letter" link in the email works as soon as it lands.

Pages tab — the whole website

Live Pages lists every page on timothystl.org, in the order they appear in the menu, with sub-pages indented under their parent. For each one you can see its web address, whether it is in the menu, whether it has changes that have not been published yet, and who last edited it. The All, Published and Drafts buttons narrow the list.

Edit page opens the same drag-and-drop editor the ministry pages use (see The page editor below), with one addition: a list of every page down the far left, so you can move from one to the next without going back to the list. A gold dot beside a page means it has unpublished changes.

Beside the block settings there is now a Page tab holding everything about the page rather than a block on it — its name, its web address, where it sits in the menu, whether it is in the menu at all, its layout, and the one-sentence summary Google shows underneath the page title.

Renaming a page changes its web address. That is normally what you want, and anyone who follows an old link is sent to the new address automatically, so nothing breaks. Sub-pages move with their parent. The homepage always stays at the top level whatever you call it.

Nothing you do here goes live until you press Publish. Every existing page already has a version waiting in the editor, built from the page as it is today — the live site keeps showing the old version until someone opens the page, looks it over, and publishes it. That is deliberate: it lets the site be moved across one page at a time.

Church details (the button at the top of the list) holds the church address, phone number, email and service times in one place. The map, the service-times panel, page sidebars and the footer of every page all read from it — change a phone number here and the whole site follows. No need to hunt through pages.

Handing a page to someone. On the Page tab, Who can edit this page assigns a page to one person. They then see only that page, and can change the words and the blocks on it — but not its name, its address, its place in the menu, or whether it exists. Blocks you tick as Set by the church office show a 🔒 in their list and cannot be removed by them at all, only edited around.

Ministries tab

Live Manage the content of ministry landing pages — Music, Stephen Ministry, Food Pantry, Urban Beekeepers, and Christmas Market. Edit page opens the drag-and-drop page editor (see The ministry page editor below), where you arrange the page yourself. Details keeps the page banner photo, the core value, whether it is listed in the menu, and a few older options. “In menu” and “Status” are two different things: unticking List this ministry in the website menu only takes it out of the header — the page stays live at its own address and every link to it keeps working. Unpublishing is what takes a page off the website. You can update the page description, button text and links, and photos without touching any code. Changes appear on the site immediately. This tab also covers Youth & Family sub-pages (/youth, /sundayschool, /confirmation, /vbs, /egghunt, /family — TinyMCE editors, what used to be a separate "Youth Pages" tab) and the Voters Assembly page (/voters — Zoom link + council document upload, what used to be a separate "Special Pages" tab).

The ministry page editor

Live On the Ministries tab, Edit page opens the page editor. A ministry page is built from blocks — a paragraph of text, a photo beside some words, a video, a list of meeting times, a button. You choose which blocks the page has and what order they go in. You cannot break the page: every setting is a choice from a short list, never a free-form number or colour.

The five things to know:

  1. Click any words on the page and type. The page in the middle is the real page. Click a heading or a paragraph and start typing. What you see is what visitors will see.
  2. Drag the rows on the left to reorder. The left-hand list is the page from top to bottom. Drag a row up or down and the page follows. On a tablet, or if dragging is awkward, click a block and use the ↑ and ↓ buttons on the little toolbar above it — or press Alt and the arrow keys with a row selected.
  3. Add a block from the panel along the bottom. Pick a group (Content, Dates, Structure, Sign up) and click a block to add it to the end of the page, or drag it to exactly where you want it.
  4. The right-hand panel changes the selected block. Spacing, background colour, text size, which side the photo sits on. Colours that would be unreadable are greyed out, and spacing only moves in fixed steps, so nothing can end up misaligned.
  5. The banner at the top is a block too. Click the title, the small label above it, or the line underneath, and type. It is the first row in the left-hand list, so you can move it or remove it like anything else.
  6. Nothing is public until you press Publish. Your work is saved as you go ("Autosaved 1:49 PM" in the top bar) but the live page does not change until you press Publish. Until then the pill in the top bar says Draft and the panel on the right lists everything you have changed.

Checking it on a phone. Use the Desktop / Tablet / Phone buttons in the top bar. Most people will see this page on a phone. Columns stack automatically; if a block is only useful on a big screen, turn off "Show on phone" in the right-hand panel and it will be left out on phones.

Photos. Click Change photo on a block, or the Photo row in the right-hand panel. Choose one already in the library, or drop a new one in. You will be asked to describe the photo before it can be used — that description is read aloud to people who cannot see it, so write what is in the picture ("The choir in the balcony at Christmas").

Stamps. A stamp is the tilted label you can put over the corner of a block — New, Upcoming, Registration open. Pick one in the right-hand panel, then click it on the page to reword it to anything you like.

Made a mess? ↺ Undo in the top bar steps back through your changes. Reset block at the bottom of the right-hand panel puts one block back to how it started. And the ▾ next to Publish lists everything published recently — Restore brings an older version back as a draft so you can look at it before anyone else does.

Publishing later. The ▾ next to Publish also lets you pick a date and time. The page goes live on its own within about fifteen minutes of that time — useful for something that should not appear until Sunday morning.

Reusing something across pages. Select a block and choose Save as reusable section at the bottom of the right-hand panel — or save a whole page from the ▾ next to Publish. Saved sections appear under Saved in the bottom panel and can be dropped onto any ministry page. Write "Contact the office" once and use it everywhere.

Your page is waiting as a draft. Every ministry page — banner, headings, paragraphs, buttons, all of it — has already been loaded into the editor for you. Nothing on the live site has changed. Open a page, look it over, fix anything that reads oddly, and press Publish when you are happy. From that point the editor is where that page is edited.

Menu tab

Live The order and shape of the menu at the top of the website and the links in the footer. A live preview of the real bar sits at the top of the screen, built from the actual items — so what you see there is what visitors get.

Drag a row by its ⠿ handle to move it. Drop it onto another item's name to tuck it underneath that item. Two levels is the limit; a third is a menu nobody can use on a phone. The footer is a flat list with no nesting.

The ✕ takes an item out of the menu — it does not delete the page. The page stays live at its address, every link to it keeps working, and it reappears in the "Live pages not in the menu" panel on the right so you can put it back with one click. Nothing is ever lost by tidying the menu.

The label can be shorter than the page name — "Visit" in the bar, "Plan a Visit" on the page itself. And the address is never stored on the menu item: if somebody renames a page, every menu entry pointing at it follows automatically. There is nothing to go back and fix.

One item should be a button. Give is it. A second button stops the first standing out, and the screen will say so.

A menu item can also point at an outside site (Word of Life, Mother's Day Out) or at a short link like /zoom. If an item points at a page that has been deleted or put back into draft, it is flagged in red rather than quietly removed — the website leaves it out so visitors never hit nothing, but it stays on this screen until you decide what to do with it.

The "Live pages not in the menu" panel is not a list of problems. A thank-you page or a one-off landing page is meant to be reachable only by its link. The panel is there so a page you made and forgot doesn't stay forgotten.

The footer is columns. Each heading — Visit, Connect, Programs, Partners — is a box you can drag links into, and dragging a link from one column to another is the same gesture as reordering inside one. Edit on a column renames it, hides it, or deletes it. Deleting a column never deletes the links in it: they come out into a "Not in a column" band and keep showing on the site, under the first heading, until you drag them somewhere. The Partners column fills itself from the four partner ministries, so there is nothing to drag into that one.

Appearance — the top bar and the newsletter strip

Live The Appearance button at the top of the Menu screen is where the header itself is edited: the church logo, the church name, the tagline under it, the colour of the bar, the gold line along the bottom, and the colour of the Give button. The newsletter sign-up strip above the footer is on the same screen — its heading, its wording, its button label, its colour, and a switch to take it off the site altogether.

This screen is the one place that saves a draft first. Everywhere else in the admin, Save means live. Here, Save keeps your changes to yourself until you press Publish to the site. That is deliberate: trying a colour or seeing how a logo crops should not put it in front of the whole congregation while you decide. While something is waiting you will see both bars, one above the other — what visitors have now, and what yours would look like — and the screen names exactly what you changed. Discard draft throws your version away and puts the screen back to what is live.

Colours are a set of swatches, not a colour picker, and that is on purpose. The writing in the bar is white and cannot be changed, so a pale colour would give you a menu nobody can read — on every page at once. The swatches are the church's own colours and every one of them is safe. Gold is not offered for the bar for exactly that reason, though you can still use it for the line underneath and for the Give button.

The logo. Choose a file and it uploads straight away; it appears at about the size of a large coin, so a square picture works best. You can show it round or square. If you clear it, the church name shows on its own. Clearing both the logo and the name is treated as a slip and the name comes back — that corner of the bar is also the link back to the homepage.

Nothing else moved. Adding, renaming, reordering or removing a menu item still takes effect straight away, as it always has — usually within a couple of minutes. Only the appearance settings wait for Publish.

Partners tab

Live Timothy has four core values — Worship, Acceptance, Christian Education, and Outreach — and one partner ministry paired to each of them. This screen is where those four records live. They appear on the website at /about/values, on the About page, and in the Our Four Values panel on the Dashboard.

Each partner has a name, a short name for where space is tight, a sentence or two about what they do, their website, and a line for anyone named alongside them — that last one is how Pastor Rall and Mary Ann, missionaries to Papua New Guinea, are named on the Christian Friends of New Americans record.

Exactly one partner per value. The system will not let you give two partners the same value; it will tell you the value is already taken rather than quietly replacing whoever was there. If a value has no partner, the list shows it as a gap and the website says so on the values page — better than looking like the church only has three values.

Tagging things with a core value

Live Ministries, news posts and Bible classes can each be tagged with one of the four values. The tag shows as a small coloured chip in the list and you can filter by it. It is what the Dashboard's Our Four Values panel counts, and what fills in the ministries listed under each value on /about/values.

Leaving something untagged is fine — not everything belongs to one value, and the screen will not nag you into a wrong answer. It does point out untagged ministries, because a ministry with no value simply will not appear in that report.

Sermons tab

Live Add and edit sermon entries. Each sermon has a title, date, preacher, series name, and YouTube link. Sermons appear on the /sermons page in reverse-chronological order.

This week's service appears on /sermons by itself. Nobody has to post a link each week — the site reads the church's YouTube channel and shows whatever went up most recently. If YouTube is unreachable, or the channel has nothing on it, the page simply shows the "Watch on YouTube" button it always had rather than an empty video box.

Two settings control it, under Settings. Worship service channel is the channel itself — a handle like @TimothySTL is enough. Only show services titled is normally blank, which means "show the newest video". Fill it in with a word like worship only if the channel starts carrying other things — a concert, a funeral — that should not appear as the Sunday service.

Christian Ed tab

Live Manage the Bible class schedule shown on the /education page — each class has a label, title, description, meeting schedule, and location. Edits appear on the site immediately.

Notices tab

Live Manage toggleable content blocks that appear on various pages — seasonal worship blocks (Advent, Christmas, Lent, Holy Week, Thanksgiving), the Community Concert announcement on the Music page, and other dynamic sections. Each block has a rich-text editor and a "Show this block on the website" checkbox. Uncheck to hide; the content stays saved for next time. See also: Seasonal worship blocks and Community Concerts above. (This tab was renamed from "Pages" — same feature, new name.)

A notice is deliberately not part of the page. That is the whole point of it living here: switching a Sunday closing off takes one click and leaves the page itself untouched. The list flags any notice you have created but never written anything in, because an empty notice shows nothing on the site and it is easy to forget you started one.

Images in any rich-text editor: Drag and drop a photo into the editor, or copy-paste one. It uploads to Cloudflare automatically — no separate upload step needed. This works in Notices, News & Events, Ministries, and Christian Ed body editors.

Links tab

Live Manage the link cards shown on the social "link in bio" page at links.timothystl.org. Each card has a title, description, icon, color, URL, and sort order. Only http:// and https:// URLs are accepted.

Staff tab

Live Manage the staff directory shown on the About page. Add or edit staff members — name, title, email, photo, and bio. The photo field is a file upload (drag/drop a headshot and it uploads automatically, up to 8MB) — no need to host the image anywhere first. After uploading, use the ↔/↕ sliders to recenter the circular crop if the photo doesn't center on the person's face by default, and the 🔍 slider to zoom in if there's too much background in the shot. Use the ▲/▼ buttons on the staff list to reorder people; new staff are always added to the end of the list. Changes appear on the site immediately.

Custom redirects can be edited or deleted in place. Giving tab

Requires Giving permission Manages everything related to giving/payment links, added 2026-07-27:

There are two giving pages, and they do different jobs.

  • give.timothystl.org is where someone actually gives — pick an amount, pick a fund, go. This is the page the Base Tithe.ly Link, Amount Tiers and Funds below all control.
  • timothystl.org/give is where someone works out how they want to give — the offering plate, bank bill pay, Thrivent, an IRA distribution, a Donor Advised Fund, leaving a gift in a will. Its "Give Online" button simply sends people to the page above.

You only ever change the Tithe.ly link in one place: the Base Tithe.ly Link below. Every giving button on the whole site follows it. If you are ever asked to paste a Tithe.ly address anywhere else on the website, something is wrong — check with whoever maintains the site first.

  • Base Tithe.ly Link — should include formId, locationId, and fundId, but not an amount — the page automatically appends the right amount (in cents) for whichever chip is picked, including a typed "other amount." Get this by generating a link for General Fund giving from Tithe.ly, then delete the trailing &amount=... before pasting it here.
  • Amount Tiers — the chip amounts shown in the interactive amount picker on give.timothystl.org (e.g. $30/$50/$100) — every chip automatically gets a working Tithe.ly link built from the Base Tithe.ly Link above, no per-tier link generation needed. The optional link field on each tier is only for the rare case where one specific amount should go somewhere else entirely (a different fund or form) — leave it blank normally. Check "Default" on the one tier that should be pre-selected when the page loads.
  • Funds — a "Give to" dropdown on give.timothystl.org (only shows up if there's more than one active fund). Each fund needs its own Tithe.ly fundId — get this the same way as the Base Tithe.ly Link: generate a link for that specific fund from Tithe.ly and copy the fundId value out of it. Leave the fund ID blank for a "General Fund" entry that should just use whatever fund is already in the Base Tithe.ly Link. When adding a new fund, real fund names from ChMS appear as click-to-fill suggestion chips above the name field (added 2026-07-27) — click one to fill in the name, then paste in that fund's Tithe.ly ID yourself; ChMS doesn't track Tithe.ly IDs so it can only suggest the name. Only affects the interactive amount picker at the top of the page — the "What Your Generosity Makes Possible" ministry ladder (left column, weekly amounts $15–$300, each with its own "Give $X" button) and the "Bigger Commitments" leadership-giving section ($5,000–$18,000/year) further down the page always give to the default fund, and their amounts/copy are hardcoded (not admin-editable — edit give-landing.js directly to change them).
  • Vendor / Market Links — one-off payment links for things like a Christmas Market vendor deposit or a rental (moved here from the old Redirects tab's "Giving Links" section). Paste in a prefilled link from either Tithe.ly or Square (the Market runs on its own separate Square account) — any web link works. Give it a short slug and a label, then share timothystl.org/<slug>. Uncheck "Active" to retire an old one without losing the record of what it was for. Gym rental invoices already generate and email their own Tithe.ly pay link automatically — nothing needs to be added here for those.

This tab has its own Giving permission (Users tab), separate from the Redirects permission — so giving-link management can be granted to office staff without also granting them access to plain site redirects, or vice versa.

Filtered Mail tab

Live Messages from the website's contact and prayer forms that were held back as spam — the marketing pitches ("we make animated videos for your website", SEO offers, and so on) that used to land in the office inbox.

Nothing is ever deleted automatically. A held message is stored here in full, along with the reasons it was flagged. If one turns out to be real, click This is real — send it to me and it is emailed to the office exactly as it would have arrived, and passed along to Connect. The person who sent it is never told their message was held, so a real sender simply gets a slightly delayed reply.

The dashboard shows a "website messages held as spam" line whenever anything is waiting, so held mail can't sit here unnoticed. Borderline messages are not held at all — they are delivered with [likely spam] at the front of the subject line, so they can be scanned or filtered in Gmail without risk of losing anything.

Worth knowing: the filter is deliberately cautious. It is far better to let a sales pitch through than to hold a real prayer request, so the rules are tuned to catch the obvious cases — bulk-mail opt-out lines, sales vocabulary, messages stuffed with links, and floods from a single address. If spam keeps getting through, the Extra protection box at the bottom of the tab explains how to turn on Cloudflare Turnstile, a quiet "are you human?" check on the forms.

Subscribers tab

Live View the email newsletter subscriber list. Shows all subscribers, their status, and when they subscribed. You can search or export the list from here.

Gym Rentals tab

Live Manage gym rental requests submitted through the website. Review pending requests, mark them approved or declined, and keep a record of past rentals. The Settings button on this tab manages the hourly rate, hold duration, Google Calendar sync, notification email, and payment link.

Payroll tab

Requires Payroll permission Runs combined biweekly payroll for church staff and MDO preschool staff — hours, PTO, hourly/salary pay, housing allowance, HSA, and 403(b) deductions, with CSV export. This data lives in a separate Supabase database, not the church's D1 database, because it also needs to read the MDO preschool's existing staff time-clock system. Access requires the dedicated Payroll permission on your account (Users tab) — it is no longer bundled with the Redirects/Settings permission.

Users tab

Admin only Manage admin portal user accounts. Create accounts for new staff, assign roles and permissions, reset passwords, and deactivate accounts that are no longer needed. The youth director has a separate account with access limited to the Ministries tab.

Changing a password is its own screen. Open the person, then use Set a new password. The screen where you tick permissions has no password box on it — that is deliberate, because a browser password manager fills a username box whenever it fills a password box beside it, and that was quietly renaming accounts and resetting passwords every time somebody edited access. For the same reason the username on that screen is locked until you press Change. Setting a new password signs that person out of the admin everywhere; they sign back in with the new one.

Audit Log tab

Admin only A timestamped log of every action taken in the admin portal — who changed what and when. Useful for tracking down unexpected changes or verifying that an update was saved.

SEO & Search Visibility

Search engine optimization was completed in April 2026. The following are already in place — no action needed unless something changes.

What's set up

  • Schema.org JSON-LD — Church structured data on the homepage with address, phone, hours, and social media links. Helps Google show a knowledge panel.
  • Per-page meta tags — Each page has its own title, description, Open Graph tags (Facebook/link previews), and Twitter Card tags. These update automatically when you navigate between pages.
  • Canonical URLs — All pages use timothystl.org (no www). The www version redirects automatically.
  • robots.txt — Tells search engines to index the site but skip /manual and /voters.
  • sitemap.xml — Lists all 25+ public pages; submitted to Google Search Console April 2026.
  • noindex — Applied to /manual, /voters, and the 404 page so they don't appear in search results.

Still pending (low priority)

  • Social preview photo — The og:image currently uses the logo. A proper 1200×630 photo of the church would improve how the site looks when shared on Facebook or iMessage. Drop a photo in /public/images/ and ask Claude to update the og:image tag.

If you add a new page that should appear in search results, ask Claude to add it to sitemap.xml and wire up its meta tags in the updatePageMeta() function in public/index.html.
