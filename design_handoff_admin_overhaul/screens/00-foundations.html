Timothy Lutheran · Admin overhaul

Foundations

Every screen in this admin is the same shell with a different middle. This page specifies the shell exactly — sidebar, header, toolbar, table, drawer, buttons, pills, toasts. Build these once, correctly, and twenty screens fall out of them. If a screen you are building does not look like its reference file, the shell is where to look first.

Type

  • Lora, weight 500 — every page heading (h1) and every panel heading. Never for UI text.
  • Source Sans 3 — everything else. Weights in use: 300, 400, 500, 600, 700. No other families.
  • Page title 25px/1.15 Lora 500 #1E2D4A. Purpose line under it 13.5px/1.5 #6A6858, max-width 56em.
  • Row text 13.5–14px. Cell subtext 12.5px #8A8271. Column headers 600 10.5px, letter-spacing .12em, uppercase, #8A8271.
  • Group labels in the sidebar 700 10.5px, letter-spacing .14em, uppercase, #D9A445.

The sidebar

This section stands as written. A brief August revision proposed replacing it with a horizontal nav; that was withdrawn — the sidebar is the navigation. What changes is that it must be always on screen, and a slim navy context bar now sits above the content saying which section you are in. See 00b-header-nav.html.

228px, fixed, never collapses. Background #1D3557, full height, its own scroll. It is identical on every screen — only the active row changes.

  • Top block — padding 16px 18px 14px, bottom border 1px rgba(237,242,247,.12). “Timothy Lutheran” at 600 16px #FAF7F1; below it “ADMIN” at 700 11.5px, letter-spacing .16em, #C9973A beside the version number at 11px #6B7F99.
  • Account line — the signed-in username, 12.5px #8598B0, padding 10px 18px, hairline border beneath.
  • Nav rows — display:flex; gap:11px; margin:1px 8px; padding:9px 12px; border-radius:9px. Resting 500 13.5px #C6D0DC. Active 600, white text, background #27496E, plus box-shadow:inset 0 0 0 1px rgba(255,255,255,.16).
  • Dot — every row starts with a 7px marker. Top-level rows: a circle, #5A7191 resting, #E0A82E active. Child rows: not a circle but an elbow — 7×7 with left and bottom 1px #5A7191 borders, radius 0 0 0 3px, transparent fill.
  • Child rows — left padding 26px instead of 12px. The five page types (Ministries, Partners, News & Events, Sermons, Christian Ed) are children of Pages.
  • Badge — a count on the right when something waits: 700 10.5px #E8C070 on rgba(201,151,58,.22), radius 999px, padding 1px 7px.
  • Foot — top hairline, “⌘K searches every section.” at 11.5px #8397AF, then “Sign out” at 12.5px #C9973A.

Header

  • Padding 20px 26px 0 on #FAF7F1. Title and purpose on the left; segmented toggle and primary action on the right; wraps on narrow widths.
  • Title h1, 25px Lora 500 #1E2D4A. Purpose 13.5px/1.5 #6A6858, max-width 56em — one or two sentences in plain English, never a feature description.
  • Primary action button: padding:10px 17px; background:#1E2D4A; color:#F5E4C0; radius:8px; 600 13.5px; hover #2A3E62. One per screen, always the “+ New …” verb.
  • Segmented toggle (Dashboard, Gym Rentals, Payroll report): track #EFE7D9, padding 3px, radius 9px, gap 2px; the selected tab is a white pill.

Toolbar

  • Padding 14px 26px 12px, gap 9px, wraps. Order is always: search field → filter chips → value chips → the count, pushed right.
  • Search: white field, 1px #E7DFD1, radius 9px, placeholder from the screen spec — “Search ministries”, not “Search”.
  • Filter chip: padding:7px 12px; radius:8px; 600 11.5px. Off — 1px #E7DFD1 on #FAF7F1, text #4A4860. On — 2px #1E2D4A, background #E7EEF7.
  • Value chips always sit after the plain chips and keep their value colours in both states.
  • Count reads “n of m shown”, 12.5px #8A8271.

Table

  • A card: #FFFDF9, 1px #E7DFD1, radius 12, overflow hidden, sitting in a 26px-padded scroll area.
  • Header row and body rows share one CSS grid string built from the screen’s fr widths, gap 12px.
  • Header: padding:11px 18px; background:#F4EFE5; border-bottom:1px solid #E7DFD1, uppercase micro-label type.
  • Row: padding:12px 18px; border-bottom:1px solid #EFE7D9; cursor:pointer. Hover lifts the background to #F7F2E9. The whole row is the hit target.
  • Row actions appear on the right on hover: a primary (“Edit”, or “Open editor” where the row opens the page editor) and a secondary (“Details”, or “⋯”).
  • A row needing attention shows an inline amber strip beneath its cells with a short reason and a “Fix” action.
  • Empty state, inside the card: a title and one line of help — “Nothing matches “x” / Try fewer words, or clear the filters”, or “Nothing here yet / Use the button above to add the first one.”
  • Under the card, where the screen has one, a single explanatory note at 13px #8A8271. It explains why the screen works the way it does — keep the wording from the spec.

Drawer

  • Right-hand panel, roughly 460px (wider on Users), full height, #FFFDF9, left border 1px #E7DFD1, with a scrim over the content behind it. It slides; it does not replace the list.
  • Head: record title 18px Lora 500, subtitle beneath at 12.5px #8A8271 — “Ministry · saved changes are logged”, “New · nothing saved yet”, “Audit entry · read-only”.
  • Fields stack with gap 16px. Label 600 12.5px #4A4860; input padding:9px 11px; 1px #E7DFD1; radius:8px; white; 13.5px; helper text beneath at 12.5px #8A8271.
  • Read-only fields use a #F4EFE5 fill instead of white. Never grey out text to signal read-only.
  • Toggle: 40×22 track, radius 999px, #4A5E3A on / #E7DFD1 off, 16px knob with a soft shadow, plus a word beside it (“Showing” / “Hidden”) — the word is not optional.
  • Choice fields are chips, not selects, wherever there are four options or fewer.
  • Foot: primary save (“Save changes” / “Create”) on the left, destructive delete on the right in #9A3B2E text. Audit entries have neither.
  • Saving closes the drawer and raises a toast.

Pills, toasts, and small parts

  • Status pill: radius 999px, 600 11px, padding 3px 10px. Good — #EDF0E4/#3F5424. Waiting — #FAF0DC/#7A5B18. Problem — #F7E4DE/#8C3A28. Neutral — #EFE7D9/#6A6858.
  • Toast: fixed, bottom centre, 26px up, #1E2D4A on #F5E4C0 text, radius 10, shadow 0 12px 34px rgba(17,30,50,.4), 2.2s.
  • Toast copy states the consequence, not the event: “Saved · written to the audit log”, “Deleted · recoverable from the audit log”.
  • Radii: 8 (inputs, chips, buttons), 9 (nav rows, search), 11–12 (cards), 999 (pills, toggles). No other values.

Copy rules

  • Plain English, sentence case, no exclamation marks. “Ministry pages”, not “Manage Ministries”.
  • Buttons name the thing: “+ New ministry”, not “+ Add”.
  • Helper text explains the consequence — what breaks, what follows, what happens on its own.
  • No emoji anywhere in the admin chrome. Icons are the small typographic glyphs already in use.
