Ministry page editor

This is where a row in Ministries lands when the office clicks it. It is a different shell from the list screens — no navy sidebar, no toolbar, no drawer. Do not try to build it out of the list chrome in Foundations; that shell stops at the moment a page opens.

The shell

  • Top bar — 58px, #1E2D4A, text #EDF2F7, padding 0 18px. Left: back to the list, the page name, and its address. Middle: undo / redo and the device switcher (Desktop · Tablet · Phone). Right: draft state, “Preview”, and the gold Publish button.
  • Body — three columns: the block outline / palette on the left, the live page in the middle, the inspector on the right.
  • Canvas background #E7E2D8; the page itself sits on #FBF8F3 at the chosen device width, centred, with a soft shadow. Device widths are real widths, not a zoom.
  • Inspector — right column, ~300px, switches between Block and Page tabs. Block settings change with the selected block; Page settings hold name, address, short link, menu placement, and the starter.
  • Nothing in the editor is modal. Selecting a block never covers the page.

Editing model

  • Text is edited on the page, in place — click the heading in the preview and type. The outline is for order and structure, never for typing body copy.
  • Blocks are added by dragging from the palette onto the page, or clicking to append. A live drop indicator shows exactly where it will land.
  • Blocks are reordered by dragging in the outline or on the page. Every mutation pushes onto an undo stack (40 deep).
  • Every change writes a plain-English line into the page’s change list — “Text + photo added”, “Welcome banner text edited” — with a timestamp. That list is what the office reads before publishing.
  • Editing a published page puts it into draft edits; the live site does not change until Publish is pressed.

Block library

GroupBlocks
StructureNotice bar, Welcome banner, Page banner, Link tiles, Button bar, Callout box, Partner logos, Spacer
ContentRich text, Text + photo, Video, Columns, Photo gallery, FAQ, Latest sermon*, News highlights*, Staff grid*, Posts feed*

* = automatic block. It reads from another section of the admin (sermon library, news posts, staff directory, calendar) and has no content to type — the inspector explains what feeds it instead of offering empty fields.

These five are the whole styling surface. There is no free colour picker, no font choice, and no custom CSS — that restraint is the feature.

The info card — the white box on the banner

The white card that sits over the navy welcome banner — service times, address, phone, directions — is not a block the office drags in. It is a slot on the banner, switched on in the inspector. Making it a separate floating block would mean asking the office to position it, and that is exactly the sort of thing this editor refuses to do.

  • Available on Welcome banner, Page banner, and Callout box. Off by default.
  • Inspector setting “Info card”: Off · Right · Left. When it is on, the banner text column narrows to make room — the card never overlaps the text and is never dragged.
  • Second setting, “Card shows”, picks the contents from a short list rather than a blank canvas: Service times, Address & directions, Contact, A short list of links, or Free text.
  • Service times and Address pull from Settings — change the service times once and every card on the site follows. Free text is the only option that asks the office to type anything.
  • The card has an optional gold eyebrow line above its contents (“JOIN US SUNDAY”), edited on the page like any other text.

How the card is drawn

PartValue

Width~34% of the banner on desktop, min 320px; full width below the tablet breakpoint, stacking under the text

Secondary line400 15px 'Source Sans 3' #4A4860
Divider1px #E7DFD1, 20px above and below, between each entry

On a navy banner the card is always white — there is no card-colour setting. One card per banner.

What is different from the page editor

  • Opens with the ministry block set already in place: page banner, rich text, text + photo, video, posts feed, form.
  • The Posts feed block only appears for ministries with “Accepts posts” switched on in the ministry drawer.
  • The Page tab of the inspector carries the ministry-only fields: core value, “In menu”, and “Links out to”.
  • Everything else — top bar, editing model, block library, block settings, publishing — is identical to the page editor. One editor, two entry points.

Publishing

  • Publish is the only thing that changes the live site, and it is a single button in the top bar.
  • After publishing, the change list clears and the state pill returns to Live.
  • Publishing is a permission (pages_edit / ministries_edit), and every publish is written to the audit log.
Get this wrong and it shows
  • Rebuilding the editor with the navy admin sidebar. The editor is full-screen and has its own chrome.
  • A form of text fields on the left and a preview on the right. Text is typed on the page.
  • Offering a colour picker, a font menu, or raw HTML.
  • Auto-publishing on save.
