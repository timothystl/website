Read against the build · 1 August 2026

Build audit

Read from timothystl/website@main (5f90460) — admin/helpers.js, admin/ui.js, admin/sections.js, admin/values.js, admin/menu.js, admin/taps.js, admin/gym.js, admin/forms.js, admin/payroll.html, admin/ministry-editor.html. The main worker is over the reader's size cap and was searched, not read line by line, so anything routed only from tlc-admin-worker.js is unverified rather than clean.

What was implemented well

  • admin/sections.js holds every title, purpose line, action label, search placeholder, filter set, column width and note as data, with a test asserting it cannot drift from the design. That is a better solution than the design asked for.
  • PALETTE in ui.js is the Foundations table, hex for hex, with the comments intact — and ui.test.mjs asserts them.
  • values.js carries all four values with the exact tint / ink / solid triplets, keyed to the database columns.
  • The sidebar's own CSS block is faithful: 228px, 9px radius rows, the raised active state rather than a gold bar, the child elbow marker, the gold badge pill.
  • menu.js is exactly the design's model — menu separate from pages, label falls back to the page, broken items flagged not dropped, two levels in the header.
  • One tinymceField() with one toolbar constant, so every rich-text field is painted the same. The design's note, honoured literally.
  • Taps are /tap1–/tap4, and the counting refuses to show a fake zero.

Deviations, worst first

1 · The sidebar is off-canvas — it is not on the screen at all Breaks the design

  • helpers.js: .sidebar{position:fixed;transform:translateX(-100%)} with .is-open sliding it in, a .sidebar-backdrop scrim, and a hamburger .sidebar-toggle in a white .util-bar. Foundations says “228px, fixed, never collapses”.
  • All the good sidebar styling below it is therefore invisible until someone finds the hamburger. This alone would make the admin feel like a different product from the prototype.
  • Consequence: .wrap{margin-left:0} and max-width:860px, so content sits in a narrow column with a large empty right side.
  • Fix: keep sidebarShell() and all its styling — it is right. Delete only what hides it: transform:translateX(-100%), .is-open, .sidebar-backdrop, .sidebar-toggle and the toggle script. Then replace the white .util-bar with the context bar in 00b-header-nav.html.

2 · Three palettes are live at once Breaks the design

  • helpers.js still opens with the pre-redesign :root: --steel:#0A3C5C, --amber:#D4922A, --charcoal:#3D3530, --gray:#7A6E60, --serif:Georgia, --sans:-apple-system…. The new tokens are appended after it, so anything not explicitly restyled renders in the old scheme and the wrong typefaces.
  • gym.js declares a third :root — --steel:#1E2D4A;--amber:#C9973A — which is closer but still not #1D3557/#C9973A as a pair, and it shadows the shell's tokens inside gym screens.
  • Everything built on the legacy classes is therefore off-design: .card (radius 14, 28px padding), .btn-primary (#0A3C5C, radius 6), inputs (radius 6, amber focus ring), .page-title (Georgia 28px, not Lora 25px), .alert, .badge-*, .filter-pill (999px pills with a navy fill, not the spec's 8px chips with a 2px border).
  • Fix: one :root. Point --steel/--amber/--charcoal/--gray/--serif/--sans at the Foundations values, delete the gym :root, and restyle .card, .btn, inputs, .page-title and .filter-pill to the Foundations numbers. Most legacy screens then land close to the design for free.

3 · Gym Rentals is almost entirely pre-redesign Breaks the design

  • Only the request queue uses renderListSection(). Roughly twenty sub-screens — settings, groups, add group, group detail, calendar test, consolidate, recurring detection, blocked dates, new booking, review booking, all bookings, price & confirm, invoices, invoice detail, recurring requests — are <div class="wrap"><div class="page-title">, i.e. Georgia headings on the old palette.
  • Their titles are Title Case (“Gym Rental Settings”, “New Booking”, “All Bookings”), not the design's sentence case.
  • The design's two Gym layouts — Calendar first and Queue first — are declared in sections.js as variants. Confirm both are actually rendered; 16-gym.html specifies both.
  • Fix: after the palette merge, convert the list-shaped ones (groups, all bookings, invoices, recurring requests, blocked dates) to renderListSection() + renderDrawer(). The genuinely form-shaped ones can stay as forms, but on the new card and button styles.

4 · Sign out was moved out of the nav, and “Connect” took its place Visible drift

  • Foundations: the sidebar foot is the ⌘K line and Sign out in gold. The build has ⌘K and Connect, with Sign out relocated to the white util bar.
  • Fix: in the new header, Sign out is the last item on the right in gold; “View site” carries the outbound link. If Connect needs a home, it is a second outbound link, not a replacement for signing out.

5 · Login, password reset and first-run setup were never redesigned Visible drift

  • loginPage(), forgotPasswordPage(), resetPasswordPage(), setupPage() all use --steel #0A3C5C, Georgia titles, #D4922A eyebrows and radius-20 cards.
  • This is the first screen anybody sees, and it currently announces the old design before the new one loads.
  • Fix: navy #1E2D4A field, card #FFFDF9 radius 12, Lora 500 title, Source Sans 3 body, primary button #1E2D4A with #F5E4C0 text at radius 8.

6 · Sidebar navy used as a content fill on Payroll Visible drift

  • payroll.html paints .tlc-pay-card-bar and .tlc-pay-tbl-bar in #1D3557. The palette comment in ui.js says it in as many words: “sidebar only, never a page”.
  • Fix: use #F4EFE5 with #8A8271 uppercase micro-label type, as every other table header does. Once the header nav is navy across the top, a second navy band in the page reads as a second nav.

7 · Value chips are missing from the filter rows Visible drift

  • sections.js gives Ministries, News & Events and Christian Ed their plain filters only. The design puts the four tinted value chips after the plain chips on each of those three screens, and values.js already holds the exact colours to draw them.
  • Fix: add a valueChips: true flag to those three configs and render them from VALUES after the plain set, keeping the value colours in both the on and off states.

8 · Filtered Mail is a legacy screen Visible drift

  • forms.js renders it as .wrap + .page-title + hand-built cards. It postdates the handoff, so there is no spec for it — but it now sits between Newsletter and Subscribers in the Email group looking unlike both.
  • Fix: it is a list of held messages with a per-message decision — renderListSection() with columns From / Subject / Held / Why, filters All · Held · Released, and renderDrawer({readOnly:true}) plus a Release action.

9 · Copy drift in two places Small

  • sections.js → links.label is 'NFC Taps\n' with a trailing newline. Harmless in HTML, wrong in a title attribute or a ⌘K result.
  • sections.js → the Sermons note reads “No recordings are attached yet, so the site shows text-only cards.” That was written when the library was assumed to exist. It is being built, so the note should describe the rule, not the current state: “A sermon with no recording shows a text-only card. Add a YouTube link and it upgrades itself.”

Suggested order

  • One — merge the palettes into a single :root and restyle the six legacy primitives (.card, .btn, inputs, .page-title, .alert, .filter-pill). Widest visual gain per line changed.
  • Two — un-hide the sidebar, and replace the white util bar with the context bar.
  • Three — login and the three account screens.
  • Four — gym sub-screens, then Filtered Mail.
  • Five — value chips, the payroll navy bars, and the two copy fixes.
