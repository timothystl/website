Timothy Lutheran Admin — round two

The July overhaul is built and live. This is what a walkthrough of the running admin turned up: Tasks 0 to 10 are done, four rulings are settled, and nine remain. One of them is a security issue and should go first.

Do this first

The renter booking page is served from admin.timothystl.org. That URL is pasted into emails to people outside the church. While one path on the admin host has to be anonymous, you cannot require a session on admin.* at the edge — and a renter who trims the URL lands on your login. Move it to timothystl.org/gym/book/<token>, redirect the old address, then lock the admin origin down. Task 17.

Four rulings, settled

These were the questions where the docs contradicted each other. They are final; where they disagree with anything in README.md, they win.

Warning rows go above The screenshot was right and §3 of the README was wrong. The band precedes the row it describes, so the eye hits the problem before the thing with the problem. Still not in the code — Task 11.
Permissions hide items, not groups Each section hides on its own permission. A group label renders only when at least one section under it survives — no orphan headings, no group hidden while a permitted section sits inside it.
Drawer buttons: Delete far left Red text, a gap, then Cancel and Save changes grouped right. Destructive is separated by distance, not by colour alone. Already correct in the build.
The sidebar stays visible 228px, fixed, always on screen at ≥900px, with a slide-over below that. Reversed once already; not reversing again.

Done — Tasks 0 to 10

Six commits landed the palette sweep, the visible sidebar, the context bar, the login screens, the gym conversions, the payroll header bars, Filtered Mail, the value chips, both copy fixes and the banner info card. Verified in the source, not taken on trust.

Two corrections came out of that audit. The definition of done said sidebar-toggle, sidebar-backdrop and translateX(-100%) should return nothing — but Task 2 item 3 requires them for the sub-900px slide-over, so that check would have failed a correct implementation. And admin/email.js was marked exempt from the palette on the reading that congregation-facing files have their own; they do not — those are the pre-redesign hexes. See Task 16.

Editor rail, Connect, arrow glyphs Both editors open with the block rail collapsed — open it by default and persist the choice. Remove "Connect" from the context bar; it links to an unrelated app. Strip every ↗. All 24 spec files are already swept.

Group edit — and a form-width rule The booking link outranks the record it belongs to; Copy is clipped off the right edge; Regenerate is a destructive action dressed as an ordinary button. The bigger find: dropping max-width:860px was right for lists and wrong for forms — single-column forms now cap at 640px, two-column at 920px, headings and tables uncapped. One shared wrapper, every form screen.
15
Five borderline hand-written routes Of 31 hand-written routes, 26 are correctly hand-written. Five are not — and the real defect is duplication, not markup: /users/new, /users/edit/ and /pages/details are second editors for records the drawer already edits. Two ways to edit one record is the problem. Answer before writing code.
16
Congregation-facing files onto the palette Reverses an earlier exemption. The hexes in email.js are not a different palette, they are the old one — the four Task 1 replaced. Inline literals only, keep the Georgia and Arial fallbacks, and leave the geometry alone: email is not a browser.
13
Homepage editor The info card renders one row per service and then drops the address and phone — services sharing a label collapse onto one line, and the card is one composed unit. Free text widens to an editable eyebrow plus bold, italic, links and line breaks. And Block width: Full / Half, so two consecutive halves pair into a row — a property of adjacent blocks, deliberately not a container you drag things into.
14
Card grid — new block Four pages on the live site use a layout the editor cannot make. Columns is plain text with no card, image or link; Link tiles is a fixed 4-up of labels. One new block covers /worship, /education, /ministries and Community partners: 2–4 up, per-card image, eyebrow, heading, body and link, all optional but the heading.
18
Renter booking — the pattern Spec screen built: screens/24-gym-booking.html. A request is a basket of slots across many dates — Tue 6–7, Wed 5–6 and 7–8 — and there is nowhere on the current page to see what you have picked. Adds a Your request panel; makes the calendar multi-date with the hour count on each held day so availability is never colour alone; moves the insurance notice to confirmation, where it is actionable; and keeps the recurring tab as a bulk way to fill the same basket.
